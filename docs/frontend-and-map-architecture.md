# Frontend and map architecture

The web application implements the design reference as URL-addressable Next.js routes rather than importing the generated prototype. Public content lives at `/`, `/methodology`, `/help`, `/privacy`, and `/terms`. Clerk protects every `/analyses/**` route on the server. Analysis screens read authoritative API state through parsed shared contracts; TanStack Query owns remote cache and polling, while browser files, upload abort controllers, and upload progress remain local ephemeral state.

The setup lifecycle is Data → Validation → Configuration → Review. Completing uploads queues an input-profile job. Saving configuration increments its revision and queues an authoritative preflight. Queueing requires the exact input revision, configuration revision, fingerprint, and matching passed preflight. The worker repeats scientific validation against the frozen snapshot before execution.

Results expose overview, diagnostics, downloads, and an interactive MapLibre map. The API maps opaque layer IDs to internal object keys, checks ownership, and proxies bounded requests to the private TiTiler service. TiTiler has no edge network or Caddy route. Point inspection samples suitability, threshold, and every published predictor and calculates the nearest occurrence from bounded WGS84 GeoJSON. Basemap style URLs and attribution are deployment-owned environment pairs; `MAP_DARK_STYLE_URL` optionally supplies the dark variant of the light basemap, and operational layers are restored after every live style switch. R normalizes and validates the result and predictor COGs, while the worker verifies their stored upload receipts. Terrain is advertised only for an explicitly selected continuous predictor whose data type, CRS transformability, resolution, metre unit, finite values, and supported elevation range all pass authoritative checks.

Durable browser mutations carry an `Idempotency-Key` that remains stable for the same in-session intent and changes with its revisions or payload. Redis records the canonical operation fingerprint and exact successful response for the remaining analysis TTL. Matching retries replay that response, mismatched reuse returns conflict, and a short claim lease serializes concurrent requests. Expiry cleanup removes indexed operation records, while lifecycle-specific draft, dataset, and configuration records share the same TTL. Signed upload-part, refresh, and download URL issuance is excluded because it does not mutate durable state and replaying expired credentials would be unsafe.

Inputs, validation state, results, map assets, and the verified ZIP bundle follow the same 48-hour lifecycle. No SQL database or permanent analysis history is introduced.

## Legal review gate

The Privacy and Terms pages are concise factual drafts reflecting Clerk authentication, temporary object storage, ownership isolation, acceptable use, and lifecycle deletion. The repository owner and qualified legal counsel must review and approve both pages before production deployment.
